# 对话带练：机器人指令结构化与 LoRA

任务：输入「向左移动2格」，让语言模型输出 `{"action":"move","direction":"left","steps":2}`。这里是格子世界的文本任务，不连接真实机器人。

每次只推进一个可观察的步骤：讲清输入与预期 → 运行或改少量代码 → 检查结果 → 对照论文解释机制。无需先自行读完论文。

## 已准备的第一步

在仓库根目录运行：

```bash
python3 projects/robot-lora/inspect_data.py
```

只使用标准库，不下载模型。输出包含一条实际样本和数据划分检查：72 条训练、12 条验证、12 条测试。先按方向与步数组合分组，再生成三种措辞，因此同一命令的改写不会跨集合。数据是原创合成示范，不能代表真实机器人指令的开放分布。

`prompt` 是提供的条件，`response` 是希望模型学会生成的标准回答。这里尚未做分词、构建 token 标签或训练。下一步围绕这一条样本观察分词结果、输入与目标的右移，以及回答区域的 loss mask。

## 已接入项目实战的带练顺序

1. 观察数据、确认任务与评测契约（本次已准备）。
2. 加载基座与分词器，保存未经微调的输出；逐项解释 token 与 causal/decoder-only 计算。
3. 构造回答区域监督，运行第一次 SFT，检查一次反向和参数更新。
4. 实现并核对一个 LoRA 线性层，理解冻结基础权重与训练 A、B。
5. 从同一基座、相同划分出发比较全量 SFT 和 LoRA-SFT；记录任务成绩、可训练参数、时间与资源。小批次先在 Mac 验证，较重实验根据实测使用 H20。
6. 仅用验证集选择配置，最后报告独立测试结果与失败样例。

拟使用 Qwen2.5-0.5B base：官方模型卡将其标为预训练后的因果语言模型。已提供 mechanics.py 的独立 LoRA 层、train.py 的 baseline / full / lora 训练入口。尚未下载该基座或完成其训练，不能将核心机制检查称为已复现论文成绩。安装、命令、显存与验收边界见上级 README。

复现范围是 LoRA 的核心机制与一个小规模任务上的对照，数据、模型与算力不等同于论文原实验，也不承诺得到原论文成绩。
